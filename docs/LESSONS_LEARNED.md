# 故障复盘与后续优化

## 实际结果

一次实际清理使用了 258 个完整标题。先以单条会话验证修复，再执行整批；长批次在 192 次提交后因页面行身份变化停止，重新扫描后处理余下 13 条。结束后的完整只读扫描中，258 个输入标题全部为 `NotFound`。逐条执行使用默认的“提交、不核验”模式，因此应区分**确认框关闭**与**最终列表扫描未找到**这两种证据。公开仓库不包含真实标题、运行编号、聊天链接或原始日志。

## 遇到的问题与处理

| 现象 | 根因或证据 | 处理办法 |
| --- | --- | --- |
| 弹出“删除聊天？”后找不到聊天侧边栏 | Chrome 的模态框打开时，无障碍树会隐藏背景控件 | 确认阶段只读取网页与弹窗；弹窗关闭后才访问侧边栏 |
| 点击“删除聊天”后卡住，10 秒时“取消”也不可用 | 页面删除请求仍在进行；真实测试中确认框约 16 秒后才关闭 | 保留至少 10 秒等待，之后只轮询确认框关闭；请求未结束时不取消，也不重复点击删除 |
| 目标已消失，但旧版核验仍超时 | 侧边栏同时少了其他行或界面行身份变化，旧版行数门槛过严 | 将逐条删除核验改为可选；默认只记录提交，结束后用独立只读扫描检查清单 |
| 多次删除后提示“界面身份已变化” | UI Automation 的 `RuntimeId` 是当前界面对象身份，列表刷新后会改变 | 安全停止并重新扫描，再处理当前仍存在的标题；不沿用旧扫描的行身份 |
| “无法加载历史记录”时无法确定剩余会话 | 部分加载的列表不能用于缺失判断 | 检出加载错误即停止；网页恢复后再做完整扫描 |
| 批量结束后检查命令仍返回代码 `2` | 已删除标题会显示 `NotFound`，当前退出码把未找到计入 `2` | 查看 `plan.json` 的状态分布；若输入全部 `NotFound`，表示当前侧边栏没有这些标题 |

## 设计启示

1. **把网页操作分成阶段。** 扫描、精确匹配、打开菜单、核对确认文字、单次提交、等待弹窗结束、结果记录分别留痕。后续问题才能定位到具体阶段。
2. **界面身份只在短时间内可靠。** 长批次不能假定最初扫描得到的全部 `RuntimeId` 一直有效；遇到变化应重新规划，而不是绕过身份检查。
3. **网络完成时间与固定等待不同。** 10 秒是最短等待，不是服务器完成承诺；可操作状态应以弹窗关闭为准，并设置上限。
4. **日志用词要与证据一致。** `ConfirmationSubmitted`、`SubmittedWithoutVerification`、`DeletedAndVerified` 表示不同强度的结论，不能混用。
5. **真实清单与公开代码分开。** 标题、聊天链接、窗口信息、运行记录都可能泄露私人信息。公开目录只保留虚构示例和模拟测试。

## 后续优化优先级

1. **自动重规划长批次。** 遇到行身份变化时，先确认没有未完成的删除请求，再做完整扫描；只对仍唯一匹配的标题继续。每次重规划都写入新的计划和输入指纹。
2. **逐条持久化结果。** 目前 `events.jsonl` 逐步写入，而 `results.json` 在整轮结束时生成。可在每条完成后写检查点，使进程被关闭时更易恢复。
3. **更清晰的退出码和汇总。** 区分“全部输入均已不存在”“部分标题未找到”“提交结果未确认”“真正故障”；提供易读的最终报告。
4. **增强定位与恢复。** 优先研究稳定的会话标识及可访问性选择器；Chrome/ChatGPT 改版时保存经过脱敏的控件诊断，而不记录聊天正文。
5. **独立的最终复核命令。** 保持删除主流程快速推进，单独提供只读扫描与对比报告，避免把列表刷新误判为删除失败。

这些改进需要继续保持现有边界：完整标题匹配、同名拒绝、确认框全文核对、单次点击，以及失焦或未知页面状态时停止。
